# Устройство проекта

```
dockbook/
  bin/dockbook.js      # CLI: dev / build / preview
  src/
    yaml.js             # свой YAML-парсер (frontmatter, .navigation.yml, openapi.yaml)
    markdown.js          # свой markdown-парсер + кастомные блоки
    openapi.js            # генерация страниц из OpenAPI-спецификации
    config.js              # загрузка и валидация dockbook.config.js
    build.js                 # сканирование папок, сборка навигации/поиска/страниц
    server.js                 # локальный http-сервер + live-reload (SSE)
  assets/                      # фронтенд, который раздаётся пользователю
    index.html
    app.css
    app.js
  docs/                         # то, что вы сейчас читаете
  example/                       # демо-проект с примерами всех блоков
```

## Почему без зависимостей

Три требования определили архитектуру: без БД, без UI/SSR-фреймворков и без
обращений в сеть во время работы сайта. Из этого следует:

- **Сборщик** — только встроенные модули Node.js (`fs`, `path`, `http`).
  markdown и YAML разбираются собственными парсерами
  (`src/markdown.js`, `src/yaml.js`) — не потому что это «интереснее», а
  чтобы не тянуть в проект ни одной npm-зависимости.
- **Фронтенд** — чистые HTML/CSS/JS. Рендеринг markdown происходит один раз,
  на этапе сборки, в Node.js; браузер получает уже готовый HTML в
  `data/pages.json` и просто подставляет его на нужный маршрут.
- **Состояние** — только файлы на диске (markdown, `openapi.yaml`,
  конфиг) и сгенерированный `outDir`. Ничего не пишется в базу, ничего не
  создаётся вне указанной папки сборки.

## Что происходит при сборке

1. `src/config.js` загружает `dockbook.config.js`, проверяет, что все
   папки из `content` существуют.
2. `src/build.js` рекурсивно обходит каждую content-папку: читает
   `.navigation.yml`, для каждого `.md`/`.mdx` парсит frontmatter и тело
   через `src/markdown.js`, строит маршрут из пути к файлу.
3. Для каждой записи `openapi` — `src/openapi.js` читает и парсит YAML,
   резолвит `$ref`, генерирует HTML-страницы по операциям.
4. Всё собранное — дерево навигации, HTML-страницы по маршрутам, плоский
   индекс для поиска — сериализуется в `outDir/data/*.json`.
5. `assets/` копируется в `outDir` как есть, плюс `theme.css` пользователя
   (или пустой файл-заглушка).

В режиме `dev` шаги 1–5 перезапускаются при изменении контента, конфига или
OpenAPI-спецификаций (`fs.watch`), а браузеру через `EventSource`
(`/__dockbook_events`) отправляется сигнал перезагрузить страницу.

## Что рендерит браузер

`assets/app.js` при загрузке страницы один раз запрашивает `data/nav.json` и
`data/pages.json` (оба — локальные файлы, без сети), дальше все переходы
между страницами обрабатываются через History API без перезагрузки:
подставляется готовый HTML нужного маршрута, перестраивается оглавление,
подсвечивается активный пункт сайдбара. `data/search.json` подгружается
отдельно и лениво — только при первом открытии поиска.
