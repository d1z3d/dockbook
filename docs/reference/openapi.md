# OpenAPI-справочник

Кроме markdown-контента dockbook умеет генерировать раздел документации API
прямо из спецификации OpenAPI 3 — без Redoc, Swagger UI и прочих внешних
инструментов.

## Живой пример

Раздел «API Reference» в сайдбаре этого сайта — не картинка и не мокап, а
самая настоящая генерация: `dockbook.config.js` в корне репозитория
подключает `example/openapi.yaml` (ту же спецификацию, что использует
демо-проект) на маршрут `/api-example`.

::cards
::card{title="Список книг → GET /books" to="/api-example/listbooks"}
Query-параметры, пример ответа 200, готовые сниппеты curl/fetch/python.
::
::card{title="Создать книгу → POST /books" to="/api-example/createbook"}
Схема тела запроса, пример 201.
::
::card{title="Получить книгу → GET /books/{id}" to="/api-example/getbook"}
Path-параметр с признаком обязательности, ответы 200 и 404.
::
::

Откройте любую карточку — это именно то, что получится из вашего
`openapi.yaml` после `dockbook build`.

## Подключение

```js
// dockbook.config.js
module.exports = {
  // ...
  openapi: [
    { spec: './openapi.yaml', path: '/api' }
  ]
}
```

- **`spec`** — путь до YAML-файла спецификации, относительно конфига.
- **`path`** — префикс маршрутов раздела на сайте (`/api/...`).

Можно указать несколько спецификаций с разными `path` — например, отдельно
публичный и внутренний API.

## Что генерируется

Для каждой операции (`get`/`post`/`put`/`patch`/`delete`/`head`/`options`)
в каждом `path` спецификации создаётся отдельная страница:
`{path}/{operationId-в-виде-слага}`. На странице:

- метод и URL;
- path-, query- и header-параметры из `parameters` (с признаком
  обязательности);
- схема тела запроса (`requestBody`), если задана;
- ответы (`responses`) с описанием и примером `application/json`, если он
  есть в `content.application/json.example`;
- готовые сниппеты запроса — `curl`, `fetch`, `python` — собранные
  автоматически из метода, URL и примера тела.

Плюс страница-оглавление на маршруте `path` со списком всех операций.

Все сгенерированные страницы автоматически попадают в сайдбар (раздел
«API Reference») и в общий офлайн-поиск наравне с markdown-страницами.

## $ref

Локальные ссылки внутри одного файла (`$ref: '#/components/schemas/Book'`)
разрешаются на этапе сборки. Ссылки на другие файлы (`./other.yaml#/...`)
не поддерживаются — для примера в `example/openapi.yaml` все схемы описаны
инлайн.

## Что не входит в справочник

Интерактивной «песочницы» с выполнением запросов из браузера нет — раз
сайт работает офлайн и не обращается в сеть, реальный `curl`/`fetch`
пришлось бы выполнять на сервере API, а не в браузере с документацией.
Сниппеты — готовый код для копирования в терминал.
