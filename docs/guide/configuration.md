# Конфигурация

`dockbook.config.js` — обычный CommonJS-модуль, без своего формата и без
парсинга: то, что он экспортирует через `module.exports`, и есть конфиг.

```js
// dockbook.config.js
module.exports = {
  title: 'Example Docs',
  description: 'Демонстрация dockbook',
  port: 4000,
  outDir: 'dist',

  content: [
    { dir: './docs', base: '/' }
  ],

  openapi: [
    { spec: './openapi.yaml', path: '/api' }
  ],

  edit: {
    repo: 'https://github.com/example/example',
    branch: 'main',
    dir: 'docs'
  }
}
```

## Поля

| Поле | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `title` | string | `'Documentation'` | Заголовок сайта: вкладка браузера, шапка, `<title>` страниц. |
| `description` | string | `''` | Пока используется только как метаданные, на страницы не выводится. |
| `port` | number | `4000` | Порт локального сервера (`dev` и `preview`). |
| `outDir` | string | `'dist'` | Папка сборки, путь считается относительно конфига. |
| `content` | массив | — | **Обязательное поле.** Папки с markdown-контентом, см. ниже. |
| `openapi` | массив | `[]` | OpenAPI-спецификации для автогенерации справочника, см. [«OpenAPI-справочник»](/reference/openapi). |
| `edit` | объект \| `null` | `null` | Если задан — под каждой страницей появляется ссылка «Редактировать эту страницу» на GitHub. |

## `content` — какие папки показывать

Это и есть ответ на вопрос «как подключить свои папки»: каждая запись —
одна папка на файловой системе плюс путь, по которому она монтируется на
сайте.

```js
content: [
  { dir: './docs', base: '/' },
  { dir: './adr', base: '/decisions', label: 'ADR' },
  { dir: '../shared-notes', base: '/notes' }
]
```

- **`dir`** — путь до папки, относительно файла конфига. Может указывать
  куда угодно на диске, в том числе за пределы репозитория с конфигом.
- **`base`** — префикс маршрута в сайте. `'/'` — раздел на корневых путях,
  `'/notes'` — все страницы папки окажутся под `/notes/...`.
- **`label`** (необязательно) — заголовок раздела в сайдбаре. Если не
  задан, берётся заголовок `index.md` папки (если он есть), иначе — `title`
  из `dockbook.config.json` (см. [«Контент и структура»](/guide/content)).

Можно указать сколько угодно записей — каждая станет отдельным разделом в
сайдбаре, в порядке перечисления в конфиге.

## `edit` — ссылка «редактировать на GitHub»

```js
edit: {
  repo: 'https://github.com/org/repo',
  branch: 'main',
  dir: 'docs'   // путь до content-папки внутри репозитория
}
```

Ссылка на странице `/guide/setup` соберётся как
`https://github.com/org/repo/edit/main/docs/guide/setup.md`.

## Перезагрузка конфига

В режиме `dev` файл конфига тоже под наблюдением: изменили `dockbook.config.js`
— сайт пересоберётся и обновится в браузере, без перезапуска CLI.
