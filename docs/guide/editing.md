# Редактирование в браузере

В режиме `dev` dockbook умеет не только показывать документацию, но и
редактировать её прямо на сайте — без открытия IDE. Правки страниц пишутся
как обычные `.md`/`.mdx`-файлы, а переименование папок — в
`dockbook.config.json` рядом с `dockbook.config.js`, поэтому дальше с ними
работает всё как обычно: `fs.watch` пересобирает сайт и обновляет страницу
через live-reload, а git видит их как самые обычные правки.

::hint{type="warning"}
Всё, что описано на этой странице, доступно только в `dockbook dev` и
только на `127.0.0.1` (сервер не слушает сеть). В `build`/`preview` — сайт
как обычно, только для чтения.
::

## Первый запуск без конфига

Если запустить `dockbook dev` в папке, где ещё нет `dockbook.config.js`,
вместо ошибки откроется приветственный экран — заголовок «Dockbook» и
кнопка «Выбрать папку с документацией».

По кнопке открывается окно выбора папки:

- список вложенных папок с навигацией внутрь/наверх («↑ Наверх»,
  «⌂ Домой»);
- путь можно вставить вручную в текстовое поле и нажать «Перейти» —
  дальше показывается его содержимое, либо сразу «Открыть эту папку»;
- под списком — подсказка о количестве markdown-файлов в текущей папке.

После подтверждения dockbook сам создаёт `dockbook.config.js` рядом (с
`title: 'Dockbook'` и выбранной папкой в `content`), пересобирает сайт и
переключается в обычный режим — без перезапуска CLI.

## Редактирование страницы

Внизу каждой страницы — ссылка «Редактировать эту страницу →». Если
локальное редактирование включено, она открывает не GitHub (как при
настроенном [`edit`](/guide/configuration)), а встроенный редактор поверх
сайта: raw markdown в текстовом поле, кнопки «Сохранить»/«Отмена».

Над текстом — панель инструментов:

- **«H ▾»** — превращает строку под курсором в заголовок нужного уровня
  (H1–H6): подставляет нужное количество `#` в начале строки, заменяя уже
  существующие, если строка уже была заголовком. Пункт «Обычный текст»
  убирает `#` и возвращает строку к обычному абзацу. Повторный выбор того
  же уровня, что уже стоит на строке, тоже снимает заголовок;
- **B**, *I*, ~~S~~, `{ }`, «Ссылка», «Картинка» — оборачивают выделенный
  текст (или вставляют плейсхолдер, если ничего не выделено);
- **«Блок ▾»** — вставляет шаблон одного из блоков, описанных на странице
  [«Markdown-блоки»](/guide/blocks): подсказка, вкладки, шаги, аккордеон,
  карточки, группа кода, таблица, Mermaid (схема/последовательность),
  PlantUML. После вставки плейсхолдерный текст внутри шаблона сразу
  выделяется — можно печатать поверх, не выделяя вручную.

Вставка идёт через `execCommand('insertText')`, поэтому `Ctrl+Z` в поле
продолжает работать как обычно.

Если у текущей страницы нет исходного `.md`-файла (например, это
сгенерированная страница OpenAPI-справочника) — редактор при открытии
покажет ошибку.

## Создание страниц и папок

Кнопка **«+ Добавить»** сверху сайдбара открывает меню из двух пунктов:

- **«Новая страница»** — запрашивает заголовок и путь (например,
  `guide/new-topic`); если раздел документации не единственный —
  дополнительно нужно выбрать, в какой из них добавить страницу. Файл
  создаётся со стартовым frontmatter (`title`) и заголовком `#`.
  Промежуточные папки в пути создаются автоматически.
- **«Новая папка»** — создаёт пустую папку по указанному пути. В сайдбаре
  она появится только после того, как внутри окажется хотя бы одна
  страница — до этого пустая папка в навигации не отображается (как и при
  обычной сборке).

## Название раздела (папки)

У каждой папки в сайдбаре — свой значок карандаша рядом с названием.
Клик открывает окно с полем «Отображаемое название», предзаполненным
текущим заголовком раздела.

Это графическая надстройка над `dockbook.config.json` из
[«Контент и структура»](/guide/content#dockbookconfigjson-заголовок-и-порядок-папки):
сохранение пишет (или обновляет) поле `title` для этой папки, не трогая
остальные поля (например, `order`). Если очистить поле и сохранить
пустым — `title` убирается из записи, и раздел возвращается к заголовку по
умолчанию (имя папки на диске, с заглавной буквы).

У корневой папки content-раздела карандаш переименования ведёт себя иначе:
если в ней есть `index.md`, заголовок берётся из frontmatter этой
страницы и переименовывается как обычная страница; если `index.md` нет —
как обычная папка, через `dockbook.config.json`. Сама корневая папка
всегда развёрнута и не сворачивается — в отличие от вложенных папок, у неё
нет шеврона.

Так решается частый случай: папка называется технически (`guide`,
`api-v2`), а в сайдбаре нужно показать нормальное название на русском —
без переименования самой папки на диске.

## `localEdit` — как выключить

Всё, что описано выше, управляется полем `localEdit` в
[`dockbook.config.js`](/guide/configuration):

```js
module.exports = {
  // ...
  localEdit: false // по умолчанию true
}
```

При `false` пропадают кнопка «+ Добавить», значки переименования папок, а
«Редактировать эту страницу» либо ведёт на GitHub (если задан `edit`),
либо не показывается вовсе. Полезно, например, если `dockbook dev`
используется для демонстрации сайта, а не для его наполнения.
