# openapi-reference Specification

## Purpose

Автоматически генерирует раздел справочника API из OpenAPI YAML-спецификации: обзорную страницу и отдельную страницу на каждую операцию, с примерами запросов на нескольких языках.

## Requirements

### Requirement: Разбор спецификации
Система SHALL читать OpenAPI-документ как YAML собственным парсером и резолвить внутренние `$ref` (в форме `#/...`) рекурсивно, с ограничением глубины рекурсии (20 уровней) для защиты от циклических ссылок; внешние или удалённые `$ref` система SHALL не поддерживать.

#### Scenario: Внутренняя ссылка на схему
- **WHEN** операция ссылается на `$ref: '#/components/schemas/User'`
- **THEN** при генерации страницы ссылка заменяется фактическим содержимым схемы `User`

### Requirement: Страница на каждую операцию
Для каждой пары путь+метод (`get`, `post`, `put`, `patch`, `delete`, `head`, `options`), присутствующей в спецификации, система SHALL генерировать отдельную страницу с маршрутом `<entry.path>/<slug>`, где `slug` строится из `operationId` (или из метода и пути, если `operationId` отсутствует).

#### Scenario: Операция без operationId
- **WHEN** операция `GET /users` не имеет `operationId`
- **THEN** маршрут страницы строится на основе slug из метода и пути

### Requirement: Содержимое страницы операции
Страница операции SHALL включать: заголовок и описание операции, таблицы path/query/header-параметров, описание тела запроса (рендер JSON Schema для `object` со свойствами и `array` с `items`, обязательные поля помечены `*`), таблицу ответов по кодам с примерами из спецификации, и блок примеров запроса.

#### Scenario: Обязательный параметр
- **WHEN** параметр помечен как `required: true`
- **THEN** в таблице параметров рядом с его именем отображается индикатор обязательности

### Requirement: Примеры запросов на нескольких языках
Каждая страница операции SHALL включать блок с примерами запроса в виде переключаемых вкладок минимум на трёх языках/инструментах: curl, JavaScript `fetch`, Python `requests`; при наличии тела запроса с примером в спецификации пример SHALL включать это тело.

#### Scenario: Операция с телом запроса
- **WHEN** операция `POST` имеет `requestBody` с `content['application/json'].example`
- **THEN** во всех трёх примерах запроса используется этот пример как тело

### Requirement: Обзорная страница раздела
Система SHALL генерировать обзорную страницу по адресу `entry.path`, содержащую заголовок и описание из `info` спецификации и список ссылок на все сгенерированные страницы операций с указанием метода и пути.

#### Scenario: Пустая спецификация без путей
- **WHEN** спецификация не содержит ни одного пути в `paths`
- **THEN** обзорная страница генерируется с заголовком/описанием, но без пунктов списка операций
