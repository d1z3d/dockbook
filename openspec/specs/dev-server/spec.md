# dev-server Specification

## Purpose

Отдаёт собранный статический сайт по HTTP локально, с опциональным автообновлением браузера при изменениях в dev-режиме и без него в режиме предпросмотра — без обращения во внешнюю сеть.

## Requirements

### Requirement: Отдача статики с SPA-фоллбеком
Сервер SHALL отдавать файлы из `outDir` по запрошенному пути; запросы к `/` или к пути без расширения файла SHALL отдавать `index.html`; запрос к существующему пути с расширением, которого нет на диске, SHALL также приводить к отдаче `index.html` (фоллбек для client-side роутинга), за исключением явного запроса `index.html`, отсутствие которого SHALL приводить к 404.

#### Scenario: Запрос клиентского маршрута
- **WHEN** браузер запрашивает `/guide/intro` (клиентский маршрут, не файл на диске)
- **THEN** сервер отвечает содержимым `index.html`, а маршрутизация происходит на клиенте

#### Scenario: index.html отсутствует
- **WHEN** запрошен `index.html` напрямую, а `outDir` не содержит этот файл
- **THEN** сервер отвечает 404 Not Found

### Requirement: Защита от выхода за пределы outDir
Сервер SHALL отклонять запросы, чей резолвленный путь выходит за пределы `outDir`, отвечая 403 Forbidden.

#### Scenario: Попытка path traversal
- **WHEN** запрошен путь, содержащий `..`, ведущий за пределы `outDir`
- **THEN** сервер отвечает 403 Forbidden

### Requirement: Live-reload через SSE (только dev-режим)
Когда `liveReload` включён, сервер SHALL предоставлять эндпоинт `/__dockbook_events` (Server-Sent Events) и инжектировать в отдаваемый `index.html` скрипт, который перезагружает страницу при получении события; сервер SHALL предоставлять функцию рассылки события `reload` всем подключённым клиентам.

#### Scenario: Файл контента изменён
- **WHEN** dev-сервер обнаруживает изменение в watched-директории и пересобирает сайт
- **THEN** все открытые вкладки браузера, подключённые к `/__dockbook_events`, автоматически перезагружаются

### Requirement: Preview-режим без live-reload и watch
Когда `liveReload` выключен, сервер SHALL отдавать статику без внедрения скрипта автообновления и без file-watch.

#### Scenario: Команда preview
- **WHEN** запущен `dockbook preview`
- **THEN** изменения файлов на диске не приводят к автоматической перезагрузке открытых страниц

### Requirement: MIME-типы ответов
Сервер SHALL устанавливать корректный `Content-Type` для известных расширений (html, js, css, json, svg, png, jpg, ico, woff2) и `application/octet-stream` для неизвестных.

#### Scenario: Запрос JSON-файла данных
- **WHEN** запрошен `/data/nav.json`
- **THEN** ответ содержит заголовок `Content-Type: application/json; charset=utf-8`

### Requirement: Автоматическая пересборка при изменениях (dev-режим)
В dev-режиме система SHALL отслеживать через file-watch все content-директории, файл конфигурации, файл `dockbook.config.json` и все подключённые OpenAPI-спецификации, с debounce-задержкой перед пересборкой, чтобы объединить серию быстрых изменений в одну пересборку.

#### Scenario: Серия быстрых сохранений
- **WHEN** пользователь сохраняет файл несколько раз подряд в течение debounce-окна
- **THEN** выполняется только одна пересборка после последнего сохранения

#### Scenario: Ошибка при пересборке
- **WHEN** после изменения файла пересборка завершается с ошибкой (например, невалидный конфиг)
- **THEN** ошибка выводится в консоль, сервер продолжает обслуживать последнюю успешно собранную версию сайта
