## Purpose

Превращает content-папки, заданные конфигурацией, и подключённые OpenAPI-спецификации в готовый статический сайт: навигацию, страницы, поисковый индекс и скопированные ассеты в `outDir`.

## ADDED Requirements

### Requirement: Обход content-папок
Система SHALL рекурсивно обходить каждую content-папку, сортируя записи по имени, пропуская скрытые файлы и папки (начинающиеся с `.`), и рассматривая только файлы с расширением `.md`/`.mdx` как страницы.

#### Scenario: Скрытый файл игнорируется
- **WHEN** content-папка содержит файл `.env`
- **THEN** этот файл не попадает ни в навигацию, ни в страницы сайта

### Requirement: Построение маршрута страницы
Система SHALL строить маршрут страницы из относительного пути файла и `base` content-раздела: расширение отбрасывается, `index` в конце пути отображается на маршрут родителя, множественные и завершающие слэши схлопываются.

#### Scenario: Индексный файл раздела
- **WHEN** обрабатывается `index.md` в корне раздела с `base: '/'`
- **THEN** маршрут страницы — `/`

#### Scenario: Вложенная индексная страница
- **WHEN** обрабатывается `guide/intro/index.md` в разделе с `base: '/'`
- **THEN** маршрут страницы — `/guide/intro`

### Requirement: Извлечение заголовка страницы
Система SHALL определять заголовок страницы по приоритету: `title` из frontmatter → текст первого заголовка из оглавления страницы → преобразованное в Title Case имя файла (замена `-`/`_` на пробелы).

#### Scenario: Заголовок не указан
- **WHEN** markdown-файл `getting-started.md` не содержит frontmatter `title` и не начинается с заголовка `#`
- **THEN** заголовком страницы становится `Getting Started`

### Requirement: Построение навигации из структуры папок
Система SHALL строить дерево навигации по структуре content-папок: файл `index.md`/`index.mdx` задаёт индексный маршрут и заголовок папки, но не становится отдельным пунктом меню; остальные файлы — пункты меню; папки без страниц и подпапок с содержимым исключаются из навигации.

#### Scenario: Пустая подпапка
- **WHEN** подпапка не содержит ни markdown-файлов, ни непустых вложенных папок
- **THEN** эта подпапка не появляется в дереве навигации

#### Scenario: Заголовок папки из nav-config
- **WHEN** для папки задан `title` в `dockbook.config.json`
- **THEN** этот заголовок используется в навигации вместо автоматически сгенерированного из имени папки

### Requirement: Сортировка пунктов навигации
Система SHALL сортировать пункты одного уровня навигации: записи с указанным числовым `order` идут раньше записей без `order` и упорядочиваются по возрастанию `order`; при отсутствии `order` у обеих записей — по алфавиту с учётом русской локали.

#### Scenario: Смешанный order
- **WHEN** в одной папке есть страницы с `order: 1`, `order: 2` и без `order`
- **THEN** итоговый порядок — сначала `order: 1`, затем `order: 2`, затем страницы без `order` по алфавиту

### Requirement: Заголовок корня content-раздела
Система SHALL определять заголовок корневой секции навигации content-раздела по приоритету: `label` из конфига → заголовок индексной страницы раздела → заголовок узла из nav-config → `'Docs'`.

#### Scenario: Заголовок не задан нигде
- **WHEN** у content-раздела нет ни `label`, ни `index.md`, ни записи в nav-config
- **THEN** заголовком секции становится `Docs`

### Requirement: Подключение OpenAPI-разделов к навигации
Для каждого элемента `config.openapi` система SHALL добавить в навигацию секцию `API Reference` со страницами, сгенерированными капабилити openapi-reference.

#### Scenario: Один OpenAPI-раздел
- **WHEN** конфиг содержит один элемент `openapi`
- **THEN** в навигации появляется одна секция `API Reference` с дочерними пунктами по операциям спецификации

### Requirement: Построение постраничной навигации (pager)
Система SHALL строить плоский список страниц для prev/next-навигации, включающий все страницы с маршрутом, обходя дерево навигации сверху вниз.

#### Scenario: Переход между соседними страницами
- **WHEN** пользователь находится на странице с индексом N в pager
- **THEN** доступны ссылки на страницы с индексами N-1 и N+1, если они существуют

### Requirement: Построение поискового индекса
Система SHALL строить поисковый индекс из всех страниц (включая OpenAPI-страницы), каждая запись содержит `route`, `title`, `description` и `text` — извлечённый из HTML plain-текст, обрезанный до 4000 символов.

#### Scenario: Длинная страница
- **WHEN** текстовое содержимое страницы после извлечения из HTML превышает 4000 символов
- **THEN** в поисковый индекс попадают только первые 4000 символов

### Requirement: Полная пересборка outDir
Система SHALL перед записью результата полностью удалять существующее содержимое `outDir` и создавать его заново.

#### Scenario: Повторная сборка
- **WHEN** `outDir` уже содержит файлы от предыдущей сборки
- **THEN** после сборки в `outDir` остаются только файлы текущей сборки

### Requirement: Запись данных сборки
Система SHALL записывать в `outDir/data/` три JSON-файла: `nav.json` (`{meta, nav, pager}`), `pages.json` (все страницы по маршруту) и `search.json` (поисковый индекс).

#### Scenario: Чтение фронтендом
- **WHEN** статический сайт открывается в браузере
- **THEN** фронтенд загружает `nav.json` и `pages.json` для первичного рендера, а `search.json` — лениво при открытии поиска

### Requirement: Копирование ассетов фронтенда и content-файлов
Система SHALL копировать весь каталог фронтенд-ассетов в `outDir`, а также копировать не-markdown файлы (изображения и т.п.) из каждой content-папки в `outDir/<base>`, сохраняя относительную структуру путей и пропуская скрытые файлы.

#### Scenario: Изображение рядом с markdown
- **WHEN** content-папка содержит `img/diagram.png`, на который ссылается markdown как `![](./img/diagram.png)`
- **THEN** после сборки файл доступен по соответствующему пути внутри `outDir`

### Requirement: Тема оформления
Система SHALL копировать `theme.css` из `config.root` в `outDir`, если он существует; иначе создавать в `outDir` файл-заглушку `theme.css` с комментарием о переопределении переменных.

#### Scenario: Пользовательская тема отсутствует
- **WHEN** в `config.root` нет файла `theme.css`
- **THEN** в `outDir` создаётся `theme.css`-заглушка, не переопределяющая никаких переменных
