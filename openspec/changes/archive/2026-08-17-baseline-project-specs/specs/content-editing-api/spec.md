## Purpose

Позволяет редактировать исходные markdown-файлы документации прямо из браузера во время `dockbook dev`, без отдельного текстового редактора, с изменениями, немедленно попадающими на диск и в live-reload.

## ADDED Requirements

### Requirement: Доступность только в dev-режиме при включённом localEdit
API `/__dockbook_api/*` SHALL быть доступен только когда сервер запущен с включённым редактированием (`config.localEdit !== false`); в режиме `preview` API SHALL быть недоступен.

#### Scenario: localEdit выключен явно
- **WHEN** конфиг задаёт `localEdit: false`
- **THEN** запросы к `/__dockbook_api/*` не обрабатываются этим модулем

#### Scenario: Команда preview
- **WHEN** запущен `dockbook preview`
- **THEN** эндпоинты `/__dockbook_api/*` недоступны независимо от значения `localEdit`

### Requirement: Защита путей от выхода за пределы content-раздела
Все операции с файловой системой SHALL резолвить переданный относительный путь строго внутри директории соответствующего content-раздела (`entry.dir`), отклоняя пути, содержащие сегмент `..` или резолвящиеся за пределы этой директории.

#### Scenario: Попытка выйти за пределы раздела
- **WHEN** запрос указывает путь, содержащий `../../etc/passwd`
- **THEN** запрос отклоняется с ошибкой `bad_path`, файл не читается и не создаётся

### Requirement: Проверка статуса редактирования
`GET /__dockbook_api/status` SHALL возвращать `{ enabled: true, entries: [{ base, label }] }` со списком доступных content-разделов.

#### Scenario: Фронтенд определяет доступность редактора
- **WHEN** фронтенд запрашивает `/__dockbook_api/status` при загрузке страницы
- **THEN** по успешному ответу с `enabled: true` фронтенд включает элементы управления редактированием в интерфейсе

### Requirement: Получение исходника по маршруту страницы
`GET /__dockbook_api/resolve?route=` SHALL находить исходный `.md`/`.mdx` файл, соответствующий маршруту страницы (перебирая content-разделы от самого длинного `base` к самому короткому, проверяя варианты `route.md`, `route.mdx`, `route/index.md`, `route/index.mdx`), и возвращать `{ entry, path, content }`.

#### Scenario: Маршрут не найден
- **WHEN** запрошенному маршруту не соответствует ни один существующий файл ни в одном content-разделе
- **THEN** сервер отвечает 404 `not_found`

#### Scenario: Пересекающиеся base разделов
- **WHEN** два content-раздела имеют базы, одна из которых является префиксом другой (например, `/` и `/api`)
- **THEN** поиск файла сначала проверяет раздел с более длинным (более специфичным) base

### Requirement: Перезапись исходного файла
`PUT /__dockbook_api/source` с телом `{ entry, path, content }` SHALL полностью перезаписывать содержимое указанного файла; путь обязан заканчиваться на `.md` или `.mdx`; родительские директории SHALL создаваться при необходимости.

#### Scenario: Успешное сохранение
- **WHEN** отправлен корректный запрос с существующим `entry` и валидным путём
- **THEN** файл на диске перезаписывается новым содержимым, изменение подхватывается file-watch и вызывает live-reload

#### Scenario: Путь без markdown-расширения
- **WHEN** `path` не заканчивается на `.md` или `.mdx`
- **THEN** сервер отвечает 400 `bad_path` и не изменяет файловую систему

### Requirement: Создание новой страницы
`POST /__dockbook_api/page` с телом `{ entry, path, title? }` SHALL создавать новый markdown-файл с шаблонным содержимым (frontmatter с `title`, значение по умолчанию — «Новая страница», и заголовок первого уровня с плейсхолдер-текстом); если `path` не оканчивается на `.md`/`.mdx`, расширение `.md` SHALL добавляться автоматически.

#### Scenario: Файл уже существует
- **WHEN** запрошенный путь страницы уже существует на диске
- **THEN** сервер отвечает 409 `exists` и не перезаписывает существующий файл

### Requirement: Создание новой папки
`POST /__dockbook_api/folder` с телом `{ entry, path }` SHALL рекурсивно создавать директорию по указанному пути внутри content-раздела.

#### Scenario: Путь занят файлом
- **WHEN** по запрошенному пути уже существует обычный файл (не директория)
- **THEN** сервер отвечает 409 `exists_as_file`

### Requirement: Переименование папки
`PUT /__dockbook_api/folder-title` с телом `{ entry, path, title }` SHALL обновлять заголовок папки через капабилити nav-config и инициировать пересборку сайта, так как заголовок папки влияет на всю навигацию.

#### Scenario: Заголовок папки изменён
- **WHEN** отправлен корректный запрос с новым `title` для существующей папки
- **THEN** заголовок папки обновляется в `dockbook.config.json`, и сайт пересобирается для отражения изменения в сайдбаре

### Requirement: Переименование страницы
`PUT /__dockbook_api/page-title` с телом `{ route, title }` SHALL точечно обновлять поле `title` во frontmatter файла, соответствующего маршруту, сохраняя остальные поля frontmatter и форматирование без полного повторного дампа YAML.

#### Scenario: Заголовок страницы изменён
- **WHEN** отправлен корректный запрос с новым заголовком для существующего маршрута
- **THEN** поле `title` во frontmatter файла обновляется, остальные строки frontmatter остаются без изменений

#### Scenario: Маршрут не найден
- **WHEN** `route` не соответствует ни одному существующему файлу
- **THEN** сервер отвечает 404 `not_found`

### Requirement: Просмотр файловой системы для выбора папки
`GET /__dockbook_api/browse?path=` SHALL возвращать содержимое директории (только поддиректории, без скрытых и `node_modules`), родительский путь, домашнюю директорию и количество markdown-файлов в текущей папке — идентично поведению мастера первого запуска.

#### Scenario: Просмотр без указания пути
- **WHEN** запрошен `/__dockbook_api/browse` без параметра `path`
- **THEN** возвращается содержимое домашней директории пользователя

### Requirement: Переключение обслуживаемой документации
`POST /__dockbook_api/switch-docs` с телом `{ path }` SHALL временно (только в памяти текущего процесса, без изменения `dockbook.config.js`) заменить обслуживаемый content на указанную папку, начать её отслеживание через file-watch, пересобрать сайт и разослать сигнал перезагрузки подключённым клиентам.

#### Scenario: Переключение на пустую папку
- **WHEN** выбранная папка не содержит `index.md`
- **THEN** сервер отвечает `{ ok: true, empty: true }`, и фронтенд может показать уведомление о пустой документации

#### Scenario: Путь не является директорией
- **WHEN** указанный `path` не существует или не является директорией
- **THEN** сервер отвечает 400 `not_a_directory`

### Requirement: Неизвестные эндпоинты
Запрос к пути внутри `/__dockbook_api/`, не соответствующему ни одному известному эндпоинту, SHALL приводить к ответу 404 `not_found`.

#### Scenario: Опечатка в пути
- **WHEN** запрошен несуществующий путь `/__dockbook_api/unknown`
- **THEN** сервер отвечает 404 `not_found`
