## Purpose

Загружает и нормализует `dockbook.config.js`, применяя значения по умолчанию и валидируя обязательные поля, чтобы остальные капабилити работали с предсказуемой, уже проверенной конфигурацией.

## ADDED Requirements

### Requirement: Загрузка конфигурационного файла
Система SHALL загружать конфиг как обычный CommonJS-модуль (`require`), поддерживая как `module.exports = {...}`, так и `export default {...}` (через `__esModule`/`default`), и сбрасывать require-cache при каждой загрузке, чтобы изменения конфига подхватывались без перезапуска процесса.

#### Scenario: Конфиг изменён во время dev-режима
- **WHEN** файл `dockbook.config.js` изменяется, пока запущен `dockbook dev`
- **THEN** следующая загрузка конфига возвращает актуальное содержимое файла, а не закэшированную версию

#### Scenario: Файл конфига не существует
- **WHEN** `loadConfig` вызван с путём к несуществующему файлу
- **THEN** система выбрасывает ошибку `Конфиг не найден: <путь>`

### Requirement: Значения по умолчанию
Система SHALL применять значения по умолчанию для не указанных пользователем полей: `title: 'Documentation'`, `description: ''`, `outDir: 'dist'`, `port: 4000`, `content: []`, `openapi: []`, `edit: null`, `localEdit: true`, `theme: {}`.

#### Scenario: Минимальный конфиг
- **WHEN** пользовательский конфиг указывает только `content`
- **THEN** остальные поля принимают значения по умолчанию

### Requirement: Обязательность content-раздела
Система SHALL требовать, чтобы `content` был непустым массивом; иначе загрузка конфига должна завершаться ошибкой.

#### Scenario: content не указан или пуст
- **WHEN** конфиг не содержит `content` или содержит пустой массив
- **THEN** система выбрасывает ошибку `В конфиге должен быть указан хотя бы один раздел content: [{ dir, base }]`

### Requirement: Нормализация content-разделов
Система SHALL приводить каждый элемент `content` к форме `{ dir, base, label }`: строковый элемент интерпретируется как `{ dir: <строка>, base: '/' }`; `dir` резолвится относительно директории конфига и обязан существовать как директория; `base` нормализуется так, что всегда начинается с `/` и не оканчивается на `/` (кроме корня).

#### Scenario: content-папка не существует
- **WHEN** элемент `content` указывает на несуществующую или не-директорную папку
- **THEN** система выбрасывает ошибку `Папка документации не найдена: <путь>`

#### Scenario: base без ведущего слэша
- **WHEN** элемент `content` задаёт `base: 'guide'`
- **THEN** после нормализации `base` становится `/guide`

### Requirement: Нормализация openapi-разделов
Система SHALL резолвить путь `spec` каждого элемента `openapi` относительно директории конфига, нормализовать `path` (ведущий `/`, по умолчанию `/api`), и исключать из списка записи, чей файл спецификации не существует, выводя предупреждение в консоль.

#### Scenario: Спецификация не найдена
- **WHEN** `entry.spec` указывает на несуществующий файл
- **THEN** запись исключается из `config.openapi`, а в консоль выводится предупреждение `dockbook: openapi-спецификация не найдена, пропускаю: <путь>`

### Requirement: Производные поля root и outDir
Система SHALL устанавливать `config.root` равным директории конфигурационного файла и резолвить `config.outDir` относительно `config.root`.

#### Scenario: Относительный outDir
- **WHEN** конфиг задаёт `outDir: 'site'`
- **THEN** `config.outDir` становится абсолютным путём `<root>/site`
