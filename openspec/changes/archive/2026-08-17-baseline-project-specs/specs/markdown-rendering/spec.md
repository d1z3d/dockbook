## Purpose

Преобразует markdown-исходники документации в HTML без сторонних зависимостей, включая расширенный набор кастомных блоков (подсказки, вкладки, шаги, аккордеон, карточки, диаграммы) поверх стандартного синтаксиса.

## ADDED Requirements

### Requirement: Frontmatter
Система SHALL извлекать YAML frontmatter из блока `---\n...\n---` в начале файла и парсить его собственным YAML-парсером; при отсутствии frontmatter возвращать пустой объект данных и исходное содержимое без изменений.

#### Scenario: Файл без frontmatter
- **WHEN** markdown-файл не начинается с `---`
- **THEN** данные frontmatter — пустой объект, всё содержимое файла передаётся в рендерер как есть

### Requirement: Базовый синтаксис
Рендерер SHALL поддерживать заголовки (`#`–`######`), абзацы, упорядоченные и неупорядоченные списки (включая вложенные и ленивое продолжение абзаца без пустой строки), цитаты, горизонтальные линии, код-блоки (` ``` `/`~~~`), GFM-таблицы с выравниванием колонок, и инлайн-разметку (жирный, курсив, зачёркнутый, `код`, ссылки, изображения).

#### Scenario: Внешняя ссылка
- **WHEN** markdown содержит `[текст](https://example.com)`
- **THEN** сгенерированный `<a>` получает атрибуты `target="_blank" rel="noopener noreferrer"`

#### Scenario: Таблица с выравниванием
- **WHEN** markdown-таблица использует разделитель `:---:` для колонки
- **THEN** соответствующие `<th>`/`<td>` получают `style="text-align:center"`

### Requirement: Автоматические якоря заголовков
Каждый заголовок SHALL получать уникальный `id`, сгенерированный транслитерацией текста в slug; заголовки уровня 1–3 SHALL попадать в оглавление (TOC) страницы.

#### Scenario: Повторяющиеся заголовки
- **WHEN** на странице дважды встречается заголовок с одинаковым текстом
- **THEN** второму заголовку присваивается уникализированный `id` (например, с суффиксом `-2`)

### Requirement: Блок hint
`::hint{type="info|warning|danger|success" title="..."}` SHALL рендериться как выделенный блок; при отсутствии `title` SHALL использоваться заголовок по умолчанию для соответствующего `type` (Информация/Внимание/Опасно/Готово), при отсутствии `type` SHALL применяться `info`.

#### Scenario: hint без атрибутов
- **WHEN** используется `::hint` без атрибутов
- **THEN** блок рендерится с типом `info` и заголовком «Информация»

### Requirement: Блок tabs
`::tabs` с вложенными блоками `::tab{label="..."}` SHALL рендерить группу переключаемых вкладок; первая вкладка SHALL быть активна по умолчанию.

#### Scenario: Несколько вкладок
- **WHEN** `::tabs` содержит три `::tab` с разными `label`
- **THEN** рендерятся три кнопки-переключателя и три панели содержимого, только первая видима изначально

### Requirement: Блок code-group
`::code-group` с несколькими последовательными код-блоками (каждый с опциональным `[label]`) SHALL рендериться как группа вкладок с кодом, где подписи вкладок берутся из `[label]` или генерируются как `#N`.

#### Scenario: code-group без меток
- **WHEN** ни один код-блок внутри `::code-group` не содержит `[label]`
- **THEN** вкладки подписываются `#1`, `#2` и так далее по порядку

### Requirement: Блок steps
`::steps` SHALL рендерить содержимое как markdown и группировать блоки, начинающиеся с заголовка `###`, в отдельные визуальные шаги; содержимое до первого `###` SHALL выводиться как обычный текст перед шагами.

#### Scenario: Три шага
- **WHEN** внутри `::steps` находятся три подряд идущих блока `### ...`
- **THEN** рендерятся три отдельных `.db-step` блока

### Requirement: Блок accordion
`::accordion` с вложенными `::accordion-item{label="..."}` SHALL рендериться как список сворачиваемых секций (`<details>/<summary>`).

#### Scenario: Раскрытие секции
- **WHEN** пользователь кликает на заголовок секции аккордеона
- **THEN** содержимое секции становится видимым (стандартное поведение `<details>`)

### Requirement: Блок cards
`::cards` с вложенными `::card{title="..." to|href="..."}` SHALL рендериться как набор кликабельных карточек-ссылок; при отсутствии `to`/`href` ссылка SHALL указывать на `#`.

#### Scenario: Карточка без ссылки
- **WHEN** `::card` не содержит ни `to`, ни `href`
- **THEN** карточка рендерится как ссылка с `href="#"`

### Requirement: Диаграммы внутри markdown
Код-блоки с языком `mermaid` или `plantuml` (fenced ` ```mermaid `), а также кастомные блоки `::mermaid`/`::plantuml`, SHALL передаваться капабилити diagrams для рендера в SVG; если рендер не удался (неподдерживаемый синтаксис), система SHALL откатываться на обычный код-блок с подсветкой синтаксиса.

#### Scenario: Неподдерживаемый тип диаграммы
- **WHEN** код-блок ` ```mermaid ` содержит `classDiagram` (не поддерживается)
- **THEN** страница отображает обычный блок кода с исходным текстом вместо SVG

### Requirement: Неизвестные кастомные блоки
Кастомный блок с именем, не входящим в известный набор (`hint`, `tabs`, `code-group`, `steps`, `accordion`, `cards`, `mermaid`, `plantuml`), SHALL рендериться как `<div class="db-block db-block--<name>">` с рекурсивно обработанным содержимым внутри.

#### Scenario: Произвольное имя блока
- **WHEN** markdown содержит `::note ... ::`
- **THEN** содержимое оборачивается в `<div class="db-block db-block--note">`
